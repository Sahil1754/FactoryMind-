Executive Overview

Abstract

TKIET MCA • Review-II

Project Essence

FactoryMind AI is an end-to-end cyber-physical predictive maintenance platform integrating Industrial IoT edge telemetry, Machine Learning, and Explainable AI (XAI) to shift manufacturing from reactive repairs to predictive intervention.

The platform monitors multi-sensor parameters (vibration RMS, temperature, current draw, and spindle RPM) across factory floor machines, detects subtle anomalies before breakdowns occur, and calculates accurate Remaining Useful Life (RUL).

Core Pillars

  • Problem Addressed: Unplanned machine breakdowns causing huge financial loss ($260K/hour average industrial downtime).
  • Hybrid Dual Architecture: High-throughput Java 21 Edge Gateway + High-precision Python 3.12 AI Engine.
  • Interactive Visual Twin: Real-time 3D WebGL Digital Twin with hot-spot fatigue inspection and live FFT harmonic spectrogram.
  • Expected Outcome: 30%+ reduction in unexpected downtime, automated work orders, and compliance with ISO 13379-1 standards.

Chapter 1

Introduction & Problem Statement

TKIET MCA • Review-II

1.1 Background & Context

Modern Industry 4.0 plants house complex machines (CNC mills, turning lathes, induction motors, and hydraulic pumps). Equipment failures halt entire production lines, causing catastrophic delays and safety hazards.

1.2 The Problem Statement

"Traditional manufacturing relies either on reactive breakdown maintenance or rigid schedule-based overhaul. Neither approach provides real-time visibility into machine health, leading to either premature part replacement or sudden catastrophic breakdowns."

1.3 Need & Industrial Significance

  • Eliminate Unplanned Outages: Continuous telemetry analysis detects micro-faults (e.g. bearing spalling, phase imbalance) 40–80 hours prior to failure.
  • Explainable Decisions: Technicians receive transparent root-cause attributions (SHAP factors) instead of black-box alarms.
  • Target Users & Beneficiaries:
    • Plant Operations Managers: Fleet KPIs, MTBF/MTTR metrics, shift reports.
    • Reliability Engineers: 3D digital twin inspection & vibration harmonics.
    • Floor Technicians: Instant work-order tickets & AI copilot advice.

Proposed System & Requirements Analysis

Functional Requirements (FR)

  • FR1 (Ingestion): Receive JSON telemetry packets over HTTP/MQTT at 2.5s intervals.
  • FR2 (Prognostics): Calculate Health Index (0–100%) and classify failure modes.

Non-Functional Requirements (NFR)

  • Latency: Inference latency < 20ms per machine telemetry packet.

  • Modularity: Decoupled Java Gateway, Python Backend, and Web Client.
  • Security: Role-Based Access Control (Admin, Engineer, Manager) with JWT tokens.
  • Compatibility: Standards-compliant with ISO 13379-1 Condition Monitoring.

Hardware Specs: Intel i5/i7 or AMD Ryzen, 8GB+ RAM, 500MB storage, optional physical ESP32 + MPU6050 vibration sensor rig.

Software Stack: Python 3.12, Java 21 OpenJDK, FastAPI, SQLAlchemy, SQLite/PostgreSQL, Three.js WebGL, HTML5 Canvas.

Chapter 6 (AI / ML)

Dataset Characteristics & ML Prognostic Algorithms

TKIET MCA • Review-II

Telemetry Dataset Description

  • Source & Calibration: Synthetic degradation models calibrated against benchmark NASA C-MAPSS and IMS Bearing run-to-failure datasets.
  • Sampling Frequency: 2.5 seconds per packet across 6 machine classes.
  • Feature Vector:
    • Temperature (°C) — Ambient baseline 65°C, critical > 85°C.
    • Vibration RMS (g) — Nominal 0.35g, fatigue threshold 0.8g+.
    • Current Draw (A) & Spindle RPM (Speed variation).
    • Cumulative Operating Hours (duty cycle aging coefficient).

AI / ML Prognostic Pipeline

  • Anomaly Scoring: Weighted normalized Euclidean distance metric from baseline parameters ($w_{vib}=2.2$, $w_{temp}=1.4$).
  • Calibrated Probability: Logistic Sigmoid transformation yielding continuous Failure Probability $P(fail) \in [0.01, 0.99]$.
  • Health Score Index: Normalized $0–100\%$ operational index.
  • RUL Estimator: Multi-stage degradation curve predicting remaining hours before functional failure (e.g., 42 hours for CNC-002).
  • Explainable AI (SHAP): Tree-impact factor breakdown showing exact percentage contribution of each physical sensor.
